# Home Assistant Config — Project Memory

## What This Repo Is

YAML configuration for a Home Assistant instance running in a container.
The main artifact is an iPad landscape dashboard (`ui-ipad-dashboard.yaml`)
registered as a YAML-mode Lovelace dashboard at `/ui-ipad`.

## Entity Naming Conventions

Entity IDs are generated by the Vitrea smart-switch integration and are **transliterated Hebrew** room abbreviations, not English words. Do not rename them.

### Pattern: `domain.{room}_{room}_{type}`

| Room | Abbreviation | Example entities |
|---|---|---|
| Living Room (salon) | `slvn` | `light.slvn_slvn_spvtym`, `fan.slvn_slvn_tqrh`, `cover.slvn_slvn_trys` |
| Kitchen (mitbah) | `mtbkh` | `light.mtbkh_mtbkh_ps`, `light.mtbkh_mtbkh_qyr` |
| Kitchen LED / entrance area | `knysh` | `light.knysh_na`, `light.knysh_knysh_qyr` |
| Office (misrad) | `mshrd` | `light.mshrd_mshrd_tqrh`, `climate.l8_103` |
| Kids Room | `mm_d` | `light.mm_d_mm_d_tqrh` |
| Kids Bathroom (mihutit) | `mqlkht` | `light.mqlkht_mqlkht_qyr`, `switch.mqlkht_mqlkht_tnvr` |
| Bedroom (hadarim) | `hvrym` | `light.hvrym_hvrym_spvtym`, `climate.l8_105`, `fan.hvrym_hvrym_tqrh` |
| Hallway (masdron) | `msdrvn` | `light.msdrvn_msdrvn_ps` |
| Balcony (mirpeset) | `mrpst` | `light.mrpst_mrpst_qyr` |

### Type suffixes (transliterated Hebrew)

| Suffix | Meaning |
|---|---|
| `spvtym` | spotlights |
| `qyr` | wall light |
| `ps` | strip / bar light |
| `tqrh` | ceiling / overhead fixture (also used for fan) |
| `trys` | blind / roller shutter |
| `khlvn` | window (secondary blind) |
| `tvrt_lylh` | night light |
| `na` | LED strip |
| `tnvr` | heater |
| `tvrh` | spotlight (entrance) |

### Climate entities

ACs are numbered sequentially: `climate.l8_101` (Kitchen 1) → `climate.l8_105` (Bedroom).

### Scripts

- Descriptive name scripts: `script.good_night_event`, `script.food_time_routine`, etc.
- UI-created scripts may have numeric IDs: `script.1766497466499` (All ACs Off).

## Dashboard Architecture

```
ui-ipad-dashboard.yaml
├── Home (path: home) — Common Areas + compact room chips
│   ├── Sidebar (280px fixed) — clock, presence, routines, git sync
│   └── Main area — Living Room, Kitchen, Entrance, Hallway, Balcony controls
├── Office (path: office, subview: true)
├── Kids (path: kids, subview: true) — Kids Room + Kids Bathroom
└── Bedroom (path: bedroom, subview: true) — Bedroom + Parents Bathroom
```

Navigation is exclusively through `tap_action: navigate` cards (no HA top bar — `panel: true`).

## Common CLI Commands

### YAML validation (run from repo root on dev machine)

```bash
# Create venv the first time
python3 -m venv /tmp/pyenv && /tmp/pyenv/bin/pip install pyyaml -q

# Validate all three main files
/tmp/pyenv/bin/python3 -c "
import yaml, sys
for f in ['ui-ipad-dashboard.yaml','scripts.yaml','automations.yaml']:
    try:
        yaml.safe_load(open(f)); print(f'OK: {f}')
    except yaml.YAMLError as e:
        print(f'ERR: {f}: {e}'); sys.exit(1)
"
```

## Away Mode Smart Logic

Three automations cooperate:

1. **Auto ON** (`away_mode_auto_on_all_away`): both persons `not_home` for 3+ min → ON
2. **Auto OFF on arrival** (`away_mode_auto_off_arrival`): any person arrives → OFF
3. **Auto OFF on activity** (`away_mode_auto_off_manual_activity`): a light/fan/switch/media turns `on` with `context.parent_id is none` (direct user action, not automation) → OFF

Manual overrides: `script.exit_home_event` (forces ON) and `script.welcome_home_event_trigger` (forces OFF).

- Create org `homeassistant`, bucket `ha_data`, and an API token
- Add the `influxdb:` block to `configuration.yaml` (see plan file)

## Design Decisions & Gotchas

- **Fan/heater toggle**: always use `mushroom-template-card` + `call-service: fan.toggle` / `switch.toggle`. The `mushroom-entity-card` with `toggle: true` opens a detail dialog on tap for entities with attributes (fans).
- **Git Pull/Push**: must use `action: call-service` + `service: shell_command.*` — `perform-action` is unreliable for shell commands.
- **Subviews**: all room tabs must have `subview: true` to hide them from the HA navigation bar (the dashboard uses `panel: true` which hides the bar anyway, but `subview: true` is still best practice).
- **Temperature sensors**: currently using `state_attr('climate.xxx', 'current_temperature')` as fallback. All templates have a comment marking where to swap in a dedicated `sensor.*` when room sensors are installed.
- **unique_id in dashboards**: never add `unique_id` to Lovelace card YAML — it does nothing and causes confusion. Only used in `configuration.yaml` for platform entries.
